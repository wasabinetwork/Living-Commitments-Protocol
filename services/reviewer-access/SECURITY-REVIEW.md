## Assets and trust boundaries

- Evidence plaintext and reviewer private keys should remain in the relevant user’s browser/device.
- R2 stores encrypted artifacts. D1 stores ciphertext metadata, signed consent envelopes, access counters, and retention timestamps.
- NEAR finalized state identifies the commitment maintainer and current wallet access keys. Current source requires 2-of-3 configured RPC providers to agree on a finalized block and exact authorization reads pinned to it. NEAR does not store reviewer contact details or plaintext evidence.
- The maintainer chooses the artifact and recipient; the reviewer controls their decryption key. The Worker can authorize, store, and serve ciphertext but must not be able to decrypt it.
- Revocation and expiry stop future downloads. They cannot erase a copy already downloaded and decrypted by a reviewer.

## Controls present in the implementation

- Exact configured browser origins; production uses its custom domain with `workers.dev` and version preview URLs disabled, while preview has its own exact Pages origin; bounded JSON bodies (12 MiB) and encrypted artifacts (at most 8 MiB).
- Canonical NEP-413 payload binding, finalized NEAR access-key checks, maintainer role checks, unique nonces, expiry checks, an approximate 60/IP/minute Cloudflare edge limiter, a 10/signer-key/minute D1 limit before NEAR authorization reads, a shared 30/minute authenticated D1 cap, and a 30/account/hour limit after key validation. Cloudflare's edge limit is per location and approximate; it is an admission-control signal, not a strict global request ceiling. The D1 signer, shared, and account quotas enforce the strict service-side boundaries. Both deployed versions require FullAccess keys for every NEP-413 action and charge the shared cap only after key validation and any required maintainer-role check; deployed rate-limit and key-type acceptance is deferred to mainnet readiness.
- The deployed Worker requires at least two usable responses from three distinct HTTPS RPC origins for the finalized block and each authorization read; every valid response must agree, so a valid dissent fails closed even if two providers agree. All contract, access-key, and chain-time reads within a request share the same block hash. Exact-preview outage/conflict acceptance and provider independence remain open.
- Maintainer approval/rejection, revocation, reviewer requests, grant listing, and downloads require a current FullAccess key. Run any remaining Finding 1 state-changing acceptance against isolated preview/testnet only; production data must not be used for fault injection.
- Private R2 binding, opaque random object keys, ciphertext digest checks, constrained scope, bounded download counts, and response cache protections.
- Scheduled expiry/revocation cleanup, orphan cleanup, retryable deletion state, and bounded retention for request, signature, and access metadata.
- Structured error logging records event and error class without request bodies, signatures, evidence, or endpoint secrets.

## INDEPENDENT AUDIT REVIEW FINDINGS

These are the historical first-pass findings; their line references and test counts predate remediation. The follow-up results below and in the linked audit supersede their unresolved status.

Found **9 issues: 2 high severity and 7 medium severity**.

1. **High — Restricted keys can impersonate reviewers.** [near.ts:278](/Users/gilbertoadon/Downloads/Develop/Living%20Commitments%20Protocol/services/reviewer-access/src/near.ts:278) accepts arbitrary `FunctionCall` keys. A key restricted to an unrelated contract successfully created a reviewer request and downloaded its approved artifact. Maintainer function-call keys also exposed all grant metadata. Require `FullAccess` for these signatures, as [NEP-413 specifies](https://github.com/near/NEPs/blob/master/neps/nep-0413.md).
2. **High — Unregistered keys can exhaust the service-wide quota.** [index.ts:645](/Users/gilbertoadon/Downloads/Develop/Living%20Commitments%20Protocol/services/reviewer-access/src/index.ts:645) consumes the shared RPC budget before checking account-key ownership. Repeating one signature from an unregistered key 30 times caused a legitimate maintainer request to receive HTTP 429. Add caller-level admission controls and protect capacity for authenticated users.
3. **Medium — Old signatures become replayable after nonce cleanup.** [index.ts:861](/Users/gilbertoadon/Downloads/Develop/Living%20Commitments%20Protocol/services/reviewer-access/src/index.ts:861) deletes nonces after 30 days, but list authorizations have no expiry. A previously rejected replay succeeded on day 31 and disclosed newly created requests. Bind signed actions to a short validity window.
4. **Medium — Retained consent signatures lose their verification data.** [0003_signed_consent_audit.sql:1](/Users/gilbertoadon/Downloads/Develop/Living%20Commitments%20Protocol/services/reviewer-access/migrations/0003_signed_consent_audit.sql:1) stores signatures without their nonces or complete signed payloads. After nonce cleanup, approval/request signatures remain but cannot be independently verified. Retain complete payloads and envelopes for the consent-retention period.
5. **Medium — Valid large artifacts are rejected.** [encoding.ts:42](/Users/gilbertoadon/Downloads/Develop/Living%20Commitments%20Protocol/services/reviewer-access/src/encoding.ts:42) uses a base64 regex that exhausts the runtime’s stack. Valid 4 MiB and 8 MiB ciphertexts returned HTTP 400 in workerd, despite the advertised 8 MiB limit. Replace it with validation that handles bounded large inputs without recursive matching.
6. **Medium — Oversized public keys consume substantial CPU before authentication.** [encoding.ts:60](/Users/gilbertoadon/Downloads/Develop/Living%20Commitments%20Protocol/services/reviewer-access/src/encoding.ts:60) performs unbounded BigInt conversion before checking decoded length. An unsigned request with a 100,000-character key took approximately 1.5 seconds to reject. Enforce encoded field lengths before decoding.
7. **Medium — Valid block hashes fail validation.** [near.ts:153](/Users/gilbertoadon/Downloads/Develop/Living%20Commitments%20Protocol/services/reviewer-access/src/near.ts:153) requires exactly 44 base58 characters. Valid 32-byte hashes can have 43 characters; three agreeing providers using such a hash still produced `NEAR_UNAVAILABLE`. Validate decoded byte length.
8. **Medium — One malformed RPC response defeats the quorum.** [near.ts:126](/Users/gilbertoadon/Downloads/Develop/Living%20Commitments%20Protocol/services/reviewer-access/src/near.ts:126) dereferences parsed JSON without checking for `null`. One provider returning JSON `null` caused failure despite two healthy, agreeing providers. Treat malformed envelopes as individual provider failures.
9. **Medium — An uncertain commit can trigger deletion of active ciphertext.** [index.ts:623](/Users/gilbertoadon/Downloads/Develop/Living%20Commitments%20Protocol/services/reviewer-access/src/index.ts:623) unconditionally deletes the uploaded object on error. Injecting an error after the D1 batch committed left an approved request and active grant pointing to deleted ciphertext. Reconcile the commit outcome before deletion, or defer cleanup to the orphan collector.

**Audit-time validation:** The auditor reported that all 15 Worker tests, 11 SDK tests, type checking, both deployment dry runs, and the scoped npm audit passed. Additional probes reportedly confirmed the findings; duplicate-approval, download-limit, revocation-race, and purge-retry checks passed. Those results predate the remediations above and have not been rerun as part of this pass.

## Follow-up acceptance findings — 2026-11-14

The [follow-up audit](ACCEPTANCE-2026-11-14.md) records the full matrix, original-nine regression results, methodology, and sanitized evidence.

1. **High — Live RPC head disagreement blocks authorization.** All 12 signed preview calls returned `503 NEAR_UNAVAILABLE`, including nine calls from verified current FullAccess keys. The configured providers repeatedly returned differing finalized heights; live request/approval/download acceptance could not complete.
2. **Medium — A dissenting third RPC reply is accepted.** Two matching block/access-key replies plus one conflicting valid reply returned 200, contrary to the matrix's conflict requirement.
3. **Medium — Approval recovery can report success for a different grant operation.** Two distinct approvals synchronized before their D1 commits both returned 201 for the same grant, although only one artifact/approval was stored. Recovery matches only `request_id`.
4. **Medium — Key-backup public metadata is not authenticated.** Replacing a backup's public key and matching fingerprint does not prevent passphrase unlock. Future artifacts use the substituted recipient, while the original private key cannot decrypt them. Ciphertext access is still required for confidentiality impact.

### Local source remediation — 2026-11-14

The four follow-up findings now have source fixes and focused regression coverage. They are deployed to isolated preview version `6b7d3105-1e63-4b18-abf7-24ce29a8709d`; production and the NEAR contract remain unchanged.

- **A1/A2 — RPC checkpoint agreement:** select the highest common finalized checkpoint covered by two providers, tolerate up to five blocks of head skew, pin authorization reads to that checkpoint, and require agreement from all valid responses. Reject valid dissent, excessive skew, future timestamps, stale checkpoints older than 60 seconds, and fewer than two usable responses. One unavailable/malformed provider remains tolerable when two agree.
- **A3 — grant recovery:** recovery is keyed by this operation's generated grant and artifact IDs and compares the complete stored grant, artifact metadata, and signed resolution envelope. Tests cover a competing approval returning `409 CONFLICT` and exact committed-operation recovery returning success.
- **A4 — reviewer key backups:** v2 binds advertised key metadata into AES-GCM additional data. Unlock also proves the decrypted private key matches the advertised public key. Legacy v1 backups are still importable after the same key-pair proof; the Console blocks access requests until the backup has been unlocked and validated.
- **NEP-413 callback compatibility:** the SDK verifies the actual Ed25519 signature and includes `callback_url` only when the wallet signed it. Tests use real signatures for both callback-present and callback-omitted envelopes.
- **Rate-limit interpretation:** Cloudflare's IP binding is documented as approximate and per-location. Strict configured boundaries remain enforced by D1 signer-key, authenticated shared, and account quotas; preview acceptance must check those independently.

Validation on the local source: Worker tests **26/26**, SDK tests **16/16**, reviewer Worker type-check plus production/preview Wrangler dry runs passed, and the Console optimized build passed. Preview `/health` returned `ok`. Using testnet signing keys locally without logging or storing key material, the synthetic preview journey for commitment `35`, evaluation `4` passed request/list/approval/grant/list/download/decryption, replay rejection (409), revocation (200), and post-revocation denial (403). Request `59c2fe12-ad2e-43b4-9424-71b036b70c2b` / grant `2b118e79-9b25-4782-bf43-4475fede4501` is revoked, has one download, and its R2 purge completed; D1 marks its artifact deleted. A separate request `1d779bf5-c626-4a14-93f5-25d06a4bcf73` is rejected with no grant. Ten signed attempts using an unregistered key returned 403, the 11th returned 429, and an authorized maintainer request-list action still returned 200. D1 shared/minute and account/hour counters were seeded at 29, each allowed one action and rejected the next, then were restored and verified absent. A concurrent 70-request edge burst saw no throttling; a sequential 90-request burst first returned 429 at request 62. This confirms configured D1 boundaries and approximate edge throttling; the edge result is not an exact quota guarantee. These test artifacts used synthetic plaintext only; production and the NEAR contract were not changed, and no on-chain transaction was submitted.
