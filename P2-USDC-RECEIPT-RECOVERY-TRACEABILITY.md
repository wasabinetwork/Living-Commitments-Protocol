# USDC receipt recovery: §7 acceptance traceability

This table maps each requirement in the acceptance matrix of
[`P2-USDC-RECEIPT-RECOVERY-DESIGN.md`](P2-USDC-RECEIPT-RECOVERY-DESIGN.md)
("Implementation and acceptance gates", items 1 through 7) to the test, capture,
or owner gate that currently evidences it. It exists so "finish the remaining
matrix" can be worked row by row instead of by TODO bullet.

Source of record: design at the revision in this repository; local VM evidence
from the pinned Sandbox 2.14.0 / protocol 88 captures listed below. Test
identifiers were read from `cargo test -p lcp-core --features
'sandbox-callback-fixture usdc-receipt-recovery' -- --list` (152 tests after
the rotation, old-epoch settlement, golden-governance, and legacy-v2
ineligibility tests added on 2026-11-19).

## Status vocabulary

| Status | Meaning |
| --- | --- |
| `PASS-OFFLINE` | Covered by unit tests or Node vectors with no VM or network dependency |
| `PASS-VM` | Covered by a pinned local Sandbox capture, reproduced by a verifier |
| `PARTIAL` | Named subcases pass; the row lists what is still missing |
| `OPEN` | No evidence, or evidence exists only as a stated intention |
| `N/A` | The requirement cannot occur because the design deliberately provides no such path; the reason is recorded |
| `OWNER` | A human, operator, or independence gate that engineering cannot close alone |

`PASS-VM` is not mainnet approval. Every VM row still depends on the independent
reproduction in `OWNER` row 7.
